# Hooks in coding-agent harnesses

Findings on what hooks are good and bad at across the uses people make of them (gating, formatting, context injection, notification, policy enforcement), collected to feed a general handbook on reasoning about whether a hook fits a failure. Findings only; no kit design, no catalogue entries, no recommendations. The narrower topic [hooks as a test gate](../hooks-as-test-gate/conclusion.md) covers hooks that run tests, the commit gate, the stop gate and loop caps, with 17 source notes; this conclusion links to those notes and does not repeat that material.

All notes in [sources/](sources/) were written from raw page text or raw GitHub API JSON (each note says how). No source was read through WebFetch. Every hook page came from the vendor and is undated or dated only by a "last updated" line; the Claude Code docs carry version numbers in text and change quickly.

## How to read the evidence

- Vendor documentation for Claude Code, Cursor, Gemini CLI, GitHub Copilot, OpenAI Codex, Windsurf (now under Devin docs), Kiro and OpenCode. First-party and precise about mechanics. It states what hooks are designed to do; none of it measures how well they work. Aider was read as a contrast; its page shows built-in lint and test commands, not hooks.
- One first-party guidance post, [Anthropic's steering blog](sources/anthropic-steering-claude-code-blog.md) (2026-06-18). It makes claims about when hooks beat instructions without giving numbers.
- Eight Claude Code GitHub issues from single users: six new ([88738](sources/claude-code-issue-88738-pretooluse-silently-stops-firing.md), [92675](sources/claude-code-issue-92675-plugin-pretooluse-not-enforced.md), [34692](sources/claude-code-issue-34692-subagent-hooks-contested.md), [33343](sources/claude-code-issue-33343-hooks-not-enforced-headless.md), [41797](sources/claude-code-issue-41797-formatter-stale-read-docs.md), [96891](sources/claude-code-issue-96891-blocked-prompt-retained.md)) and two from the test-gate topic ([40117](../hooks-as-test-gate/sources/claude-code-issue-40117-agent-bypasses-precommit.md), [55754](../hooks-as-test-gate/sources/claude-code-issue-55754-stop-hook-loop.md)). They are practitioner reports, unverified by us, and none gives a frequency. Several were closed by a stale bot with no vendor comment, so "closed" carries no information about whether the problem was fixed.
- Nothing found compares hook-based control with instruction-based control on outcomes, and nothing measures how often hooks fail to fire, how much run time or context they cost, or how often agents route around them.

## What a hook is and where it fires

Every harness read describes a hook as a script (or, in some harnesses, an HTTP call, an MCP tool, an LLM prompt or an in-process function) that the harness, not the model, runs at a fixed lifecycle point, passing event JSON and reading a result. Claude Code names three cadences: per session, per turn, and on every tool call ([reference](sources/claude-code-hooks-reference-events-output-security.md)). The points differ by harness, which changes what a hook can see and do:

- Claude Code has the widest set (session start and end, prompt submit, pre and post tool use, stop, notification, subagent start and stop, compaction, config change, file and directory change, worktree, model switch and more). Cursor has agent hooks, separate Tab-completion hooks and a workspace-open hook ([note](sources/cursor-hooks-categories-and-failure-modes.md)). Gemini CLI adds model-level hooks: BeforeModel, AfterModel, BeforeToolSelection ([note](sources/gemini-cli-hooks-overview.md)). Codex and Copilot cover tool, prompt, stop, session and compaction events ([Codex](sources/openai-codex-hooks-runtime-and-context.md), [Copilot](sources/github-copilot-hooks-surfaces-policy-and-cloud.md)). Windsurf lists pre and post hooks for file read, file write, command and MCP tool use, plus prompt and response hooks, with no stop-and-continue or context-injection event on the page ([note](sources/windsurf-cascade-hooks.md)). Kiro adds file-create, save and delete triggers that fire only for agent-made changes ([note](sources/kiro-hooks.md)). OpenCode's mechanism is an in-process plugin with tool before and after handlers ([note](sources/opencode-plugins.md)).
- What a hook sees is the event payload: the tool name and input before a call, the tool result after it, the prompt, the last assistant message at stop, the transcript path. It does not see the model's intent. Claude Code documents that the transcript file "may lag the in-memory conversation" ([reference](sources/claude-code-hooks-reference-events-output-security.md)).
- Which events can block differs and is not uniform within one harness. In Claude Code, exit code 2 blocks PreToolUse, UserPromptSubmit, Stop, PostToolBatch, PreCompact and a few others but not PostToolUse ("the tool already ran"), Notification, SessionStart, SessionEnd or InstructionsLoaded. Windsurf and Kiro give the same split: pre events can block, post events cannot. Cursor's sessionStart is "fire-and-forget"; Copilot's notification hook "never blocks the session".

## Who judges: deterministic code, or a model

Most hooks are code (a shell command, HTTP endpoint or function) whose verdict is exactly what the script returns. Anthropic says "All hooks are deterministically triggered" while only command, HTTP and MCP-tool handlers "execute deterministically"; prompt and agent hooks "use Claude's judgment" ([blog](sources/anthropic-steering-claude-code-blog.md)). Prompt-type hooks exist in Claude Code (a single Haiku call by default, 30 second default timeout; agent hooks 60 seconds and marked experimental), Cursor (a "fast model", command-only in cloud agents) and Kiro (agent actions that inject a prompt, described as steering the agent). So two things are called a hook: a computational sensor and an inferential one, and the same harness feature name covers both. Trigger determinism is a separate property from verdict determinism: the harness always fires the event, which is not the same as the hook always seeing the action (see below). No source measures the accuracy of model-judged hooks.

## Bypass, coverage and silent non-enforcement

Sources agree that a hook is stronger than an instruction and disagree with each other about how complete its coverage is.

- The vendor claim. Anthropic: an instruction "Claude will follow ... most of the time, but when under pressure, in a long session or an ambiguous situation, or due to a prompt injection ... the model can fail to follow a prompted rule. A real guardrail needs to be deterministic, and the enforcement methods are hooks and permissions"; managed settings "are the only way to enforce a deterministic, organization-wide guardrail" ([blog](sources/anthropic-steering-claude-code-blog.md)). No study is cited. The one incident in the test-gate topic ([issue 40117](../hooks-as-test-gate/sources/claude-code-issue-40117-agent-bypasses-precommit.md)) is a single report of an agent ignoring memory-file rules and skipping a git hook.
- Vendors document their own gaps. Claude Code: the `if` filter is "best-effort", so "use the permission system rather than a hook to enforce a hard allow or deny" ([guide](sources/claude-code-hooks-guide-uses-and-limitations.md)). Codex: "Some specialized tool paths can opt out of the default hook path. Treat tool hooks as a useful guardrail, not a complete enforcement boundary"; hosted tools such as web search do not use the hook path, and later `write_stdin` input does not re-run PreToolUse ([note](sources/openai-codex-hooks-runtime-and-context.md)). Windsurf and Kiro pages give no such caveat; absence there is not evidence of full coverage. Kiro's file hooks fire only for agent changes.
- Fail-open versus fail-closed is a per-harness fact. Claude Code: only exit 2 (or valid JSON) blocks; exit 1, invalid JSON, plain-text stdout, a mistyped or non-executable script path (exit 127) and a timeout all let the action proceed ("leaves the gate silently disabled") ([reference](sources/claude-code-hooks-reference-events-output-security.md)). Cursor: other exits fail open unless `failClosed: true`, though permission hooks block on invalid JSON. Copilot: preToolUse fails closed on crash and non-zero exits but always fails open on timeout, "even when the hook was deployed by an administrator as policy". Gemini and Windsurf: other exit codes let the action proceed. Codex: unsupported output fields mark the hook failed and "continue the tool call". Details of the test-gate variants are in the [earlier conclusion](../hooks-as-test-gate/conclusion.md).
- Silent non-firing reports. [Issue 88738](sources/claude-code-issue-88738-pretooluse-silently-stops-firing.md): one session's PreToolUse hook stopped running for the rest of the session with no error, while a concurrent session stayed hooked; the reporter's measurement (per-call correlation with the hook's own log, 19 of 52 calls unhooked, including a `git commit` and `git push`) is careful, but it is one unreproduced case. [Issue 92675](sources/claude-code-issue-92675-plugin-pretooluse-not-enforced.md): plugin-sourced PreToolUse hooks did not block in interactive sessions, and JSON deny did not work from a plugin in either mode, while a `settings.json` hook did block. [Issue 33343](sources/claude-code-issue-33343-hooks-not-enforced-headless.md) (v2.1.73, `-p` mode, closed by a bot) claims hooks did not fire in headless runs, which the current guide contradicts by saying `-p` runs treat committed hooks as trusted and PreToolUse denies even under `--dangerously-skip-permissions`. [Issue 34692](sources/claude-code-issue-34692-subagent-hooks-contested.md) claims subagent tool calls skip hooks; a later commenter's test says they fire with `agent_id` set, and the reference says they run in subagents. These reports conflict with the docs or with each other; what they establish is that users found hook coverage hard to trust and had no way to check it. Comments in 88738 make the same point: a hook that does not fire looks identical to one with nothing to block, and asks for a hook invocation counter, which no vendor page read provides.
- Who can turn a hook off. Claude Code: `disableAllHooks` in user, project or local settings, and the agent can edit hook config ("ask Claude to make the change"), with live reload; managed hooks cannot be disabled from below and `allowManagedHooksOnly` blocks non-managed hooks ([reference](sources/claude-code-hooks-reference-events-output-security.md); permission-mode protection of `.claude` paths is in the [earlier conclusion](../hooks-as-test-gate/conclusion.md)). Copilot: policy hooks in root-owned machine files cannot be disabled by `disableAllHooks`. Cursor: enterprise and team hooks take priority; Codex: managed hooks count as trusted by policy; Gemini: system settings sit below project settings in precedence, and it warns when a project hook's command changes. So whether a hook is bypassable by the person or agent depends on which settings tier holds it; only administrator-tier hooks are described as beyond user override.
- Hooks bind only the harness they are in. Git hooks are skippable with `--no-verify` and per-clone; the [earlier conclusion](../hooks-as-test-gate/conclusion.md) covers that and the CI backstop argument. No source read here compares hooks with CI on coverage.

## Costs: run time, context, maintenance

- Run time. Hooks run synchronously in the agent loop in Gemini ("slow hooks delay the agent loop") and Claude Code (command hooks block unless `async: true`; async output "is delivered on the next conversation turn" and there is "no deduplication across multiple firings"). Matching hooks run in parallel or concurrently (Claude Code, Codex), so one hook's deny does not stop a sibling's side effects. Defaults: Claude Code 10 minutes for command hooks, 30 seconds for prompt-submit and model-switch, 10 seconds for MessageDisplay, 1.5 seconds shared for SessionEnd; Gemini 60 seconds; Copilot 30 seconds; Codex 600 seconds; Kiro 60 seconds; Cursor "platform default". Gemini's page recommends narrow matchers to avoid spawning a process for irrelevant events and warns that AfterModel fires on every chunk. No source measures hook overhead per tool call.
- Context. Anthropic rates hook context cost "Low", contrasting with CLAUDE.md where "every line costs tokens whether relevant or not"; most hook output does not reach the model unless the hook returns it, and a blocking hook's stderr does ([blog](sources/anthropic-steering-claude-code-blog.md)). A hook that injects context costs what it injects: Claude Code caps each injected string at 10,000 characters (larger goes to a file the model is not asked to read), Codex defaults to 2,500 tokens per handler and warns that context from many hooks "adds up and can degrade model performance", with no measurement. Injected context can go stale: for mid-session events Claude Code replays saved text on resume instead of re-running the hook, though SessionStart hooks run again.
- Maintenance. Hook configuration lives in several places (user, project, local, managed, plugin, frontmatter), in a harness-specific JSON schema; Kiro's format changed across IDE 0.x, 1.0 and CLI 3.0 with a migration command; Cursor can import Claude Code hooks (details unread). Scripts depend on the machine: `jq` must exist, scripts must be executable, shell profiles that echo text break JSON parsing (Claude Code and Gemini both name this as the most common failure), Windows shells differ (Claude Code, Gemini, Copilot each carry Windows notes). Cloud variants differ again: Copilot cloud agent honours only `bash`, has a restricted network and an ephemeral disk; Cursor cloud agents skip user hooks, sessionStart and prompt hooks and do not run hooks in early read-only turns. No source measures the maintenance burden or how often hooks go stale.
- Security cost. Hooks are code run with user permissions: "Command hooks execute shell commands with your full user permissions" (Claude Code); "Hooks execute arbitrary code with your user privileges" (Gemini, which lists exfiltration of prompts and environment variables and, off by default, environment redaction). Repository-committed hooks run on cloning, guarded by trust gates that differ: Claude Code holds hooks until the workspace is trusted in interactive sessions but treats the folder as trusted with `-p`; Codex records trust against a hash and skips changed hooks until reviewed; Gemini fingerprints project hooks by name and command; Cursor and Windsurf run project hooks only in trusted workspaces.

## What a failure looks like

- A block returns reason text to the agent, so a working deny is a clear signal: Claude Code passes stderr to the model; Windsurf shows it to the agent. The stop variants convert a block into another turn (see the earlier conclusion for loop caps).
- A hook that cannot act fails silently in the ways listed above (fail-open exit codes, timeouts, unparsable output, mistyped path, hooks not loaded, session-level non-firing). The documented visible traces are a "hook error" notice in the transcript (Claude Code), logs, a Hooks output channel (Cursor) or a `/hooks` panel with counts (Gemini). Only one source ([88738](sources/claude-code-issue-88738-pretooluse-silently-stops-firing.md)) documents a failure that had no trace at all, and it is one report.
- Post-event hooks cannot undo. Claude Code: "PostToolUse hooks can't undo actions since the tool has already executed"; `updatedToolOutput` changes only what Claude sees, and telemetry captures the original output. A blocking verdict from a post hook, where available, acts on the next model call, not on the tool effect.
- A block can leave residue. [Issue 96891](sources/claude-code-issue-96891-blocked-prompt-retained.md) reports a blocked UserPromptSubmit prompt still written twice to the local transcript and redisplayed, though the model never saw it, against a docs line saying the prompt is erased. One report.
- A hook that changes files behind the agent's back interacts with its edit flow. Claude Code added a warning when a formatter or linter command modifies a previously read file ([issue 41797](sources/claude-code-issue-41797-formatter-stale-read-docs.md), the changelog line is quoted second-hand); the hooks guide's Prettier example does not mention it. Aider's page describes a formatter's non-zero exit being mistaken for a lint error and a run-twice wrapper as the workaround ([note](sources/aider-lint-and-test.md)).
- Multiple hooks combine by rule: Claude Code and Cursor take the most restrictive decision (deny over ask over allow); for rewrites (`updatedInput`) the last hook to finish wins, "the order is non-deterministic".

## Uses, as the sources describe them

- Gating (block a tool call, prompt or command). Described by every vendor. Pre events only. The Claude Code page's own worked example is a PreToolUse script exiting 2 for protected paths. Hooks act before the permission check in every mode, so a deny holds even in `bypassPermissions`; an allow cannot override a deny rule ("Hooks can tighten restrictions but not loosen them") ([guide](sources/claude-code-hooks-guide-uses-and-limitations.md)). Matching commands by text is best-effort (see the Bash matching rows in the [reference](sources/claude-code-hooks-reference-events-output-security.md) and the test-gate notes).
- Formatting and linting after edits. Anthropic's example of a job better done by a hook than an instruction: "The model choosing to run a formatter is different from the formatter running automatically." Cursor's quickstart, Windsurf, Kiro and Gemini list the same use. Costs named: the stale-read interaction above; Kiro's file hooks fire only for agent edits, not manual saves. Aider does the equivalent with a built-in lint command after each edit.
- Context injection. Available in Claude Code (SessionStart, UserPromptSubmit, tool events, Stop), Gemini, Codex, Copilot (sessionStart, notification, subagentStart, postToolUse) and Cursor (sessionStart). Claude Code's page says static conventions belong in CLAUDE.md ("It loads without running a script") and reserves hooks for state that changes: branch, feature flags, open issues, recent CI results, which test command applies to the edited file. It advises factual phrasing, since text "framed as out-of-band system commands can trigger Claude's prompt-injection defenses". The page also gives re-injection after compaction through a SessionStart hook with a `compact` matcher, and Anthropic's table says hooks "bypass compaction entirely" while CLAUDE.md is re-read after compaction; the blog does not say whether the model follows injected text as reliably as CLAUDE.md text, and no measurement was found. Windsurf's page shows no context-injection output. Copilot's config-file userPromptSubmitted hooks have their output dropped.
- Notification. Claude Code Notification hooks ignore exit code and stderr; a hook can emit a desktop notification through an allowlisted `terminalSequence`, honoured only in interactive sessions. Copilot's notification hook is fire-and-forget and does not fire in the cloud agent. OpenCode's example fires on `session.idle`. Nothing about failure of notification hooks was found.
- Policy enforcement and audit. Every vendor pairs hooks with an administrator tier: Claude Code managed settings and `allowManagedHooksOnly`, Cursor enterprise (MDM) and team hooks, Copilot policy files, Codex managed hooks, Gemini system settings, Windsurf system-level hooks. Uses named: logging every command or prompt, secret and PII scanning (Cursor partners: Semgrep, Snyk, Endor Labs, 1Password; vendor marketing, no results), and blocking commands. Cloud variants differ: Copilot policy hooks are not supported in the cloud agent; Cursor enterprise hooks do run in cloud agents. Claude Code also has HTTP hooks, with an allowlist (`allowedHttpHookUrls`), for sending events off the machine.
- Continuing the agent (stop hooks), test gates and their loops: see the [earlier conclusion](../hooks-as-test-gate/conclusion.md).

## Hooks beside neighbouring controls

- Instruction files. Anthropic's guidance, from one vendor: reliable and prohibited behaviour belongs in a deterministic control, procedures in skills, static facts in CLAUDE.md; hooks cost little context, instruction files cost tokens on every line; a shared CLAUDE.md "grows the way any unowned config file does". Claude Code's reference itself says static instructions belong in CLAUDE.md, not in a hook. Whether instructions are in fact followed less reliably than hooks fire is asserted, not measured (the repo's [AGENTS.md content research](../agents-md-content/conclusion.md) has measured evidence about instruction files alone, not a comparison with hooks).
- Permissions. Claude Code presents permissions and hooks as the two enforcement methods and says to prefer permissions for hard allow and deny, since hook matching is best-effort. Hook denies survive `--dangerously-skip-permissions`; permission prompts do not exist in `-p` mode without a callback, so hooks stand in.
- Git hooks and CI. Git hooks are skippable with `--no-verify` and not copied on clone; CI runs where the agent cannot reach. That is the test-gate topic's finding; this topic found no additional source comparing them for non-test uses.
- Tool-level checks. Aider runs lint and test commands after edits as built-in settings ([note](sources/aider-lint-and-test.md)); OpenCode uses in-process plugins; neither is described as a fail-open shell hook. Model-judged hooks overlap with review by another model; not researched here.

## Unverified, thin or contested

- Frequency of any hook failure (non-firing, bypass, loop, fail-open on timeout): every source is a single report; no measurement.
- Whether hooks make an agent's behaviour more reliable than instruction files: asserted by Anthropic, not measured. No source compares outcomes with and without a hook.
- Whether the non-firing claims in the Claude Code issues still hold: 33343 and 34692 predate current docs that contradict them; 88738 and 92675 are open and unreproduced by us. Nothing here tests any hook.
- Windsurf, Kiro and OpenCode pages say nothing about timeouts, fail-open behaviour, loop caps or coverage gaps; that is absence on the page.
- Kiro's subpages, Cline's hooks page (unreadable, a JavaScript shell), Cursor's third-party hooks page, the Claude Code security-guidance plugin, the Copilot VS Code variant and the Claude Code changelog were not read. Codex was read as a whole page body; whether hooks behave the same across Codex surfaces (CLI, IDE, cloud) was not checked.
- Gemini CLI pages carry a banner that Antigravity CLI replaced it for some tiers on 2026-06-18; hook support there is unchecked.
- Model-judged hooks: mechanics documented (Claude Code, Cursor, Kiro agent actions); accuracy, latency in practice and cost not measured or documented beyond default timeouts.
- Whether injected context is followed as reliably as instruction-file text, and how much hook-injected context degrades performance (Codex warns, no data): unknown.
- Vendor pages are undated (Gemini and OpenCode give a "last updated" line) and change; details such as defaults and event lists were read on 2026-09-26.
