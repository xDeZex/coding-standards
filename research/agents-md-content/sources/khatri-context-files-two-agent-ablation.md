# Do Context Files Help Coding Agents? A Two-Agent Ablation Study on Real Repositories

Re-read 2026-09-26: full paper PDF (arxiv.org/pdf/2607.27250, pdftotext), not the abstract page and not a summarising tool. The earlier version of this note covered only the abstract and missed the injection-strategy comparison and the test-suite finding below.

Preprint (Prakhar Khatri, independent researcher, single author), arXiv 2607.27250v1, 28 Jul 2026. Not peer reviewed as far as the paper shows.

- Design: 17 tasks from 3 Python repositories (pdm, firebase-admin-python, opshin), mined from merged PRs and graded by the PR's own hidden tests; Claude Code (claude-sonnet-4-6, 15 tasks) and Codex CLI (gpt-5.5, 17 tasks); 3 repeats; 288 evaluated runs. Files were chosen as high quality (own rubric, 248 to 1,236 words). Three context strategies: NONE; ALWAYS ON (the full AGENTS.md injected into the system prompt, or prepended to the user prompt for Codex); SELECTIVE (topic-organised wiki files in the workspace, found through a system-prompt hint and read on demand with the Read tool). For only one repository (opshin) is the SELECTIVE corpus the same 256-word content as the AGENTS.md; for pdm and firebase it is an auto-generated wiki about 10 and 18 times longer, which the paper calls a confound. SELECTIVE is on-demand file retrieval, not a skill.
- Correctness: pass rates (none / always on / selective) were Claude 53.3% / 55.6% / 55.6% (24, 25, 25 of 45) and Codex 58.8% / 56.9% / 52.9% (30, 29, 27 of 51); omnibus permutation p of 1.00 (Claude) and 0.66 (Codex). Equivalence testing bounds pairwise differences under 10 points (Claude) and 15 points (Codex); the paper itself notes this is descriptive, not a powered equivalence claim, and that the study has low power (a 30-point effect is caught only 57% of the time; about 120 to 200 tasks would be needed to detect 10 points at 80% power). On 4 Codex-borderline tasks NONE scored 58% versus 42% for ALWAYS ON and SELECTIVE.
- Failure triage: near-miss failures were attributed to implementation skill (feature design, pattern selection, wiring), not missing repository knowledge; a probe on two near-miss tasks found the real AGENTS.md never turned a failure into a pass. Author's suggestion for prior contradictions: the tasks where context could matter differ by agent (Spearman 0.75 between per-task pass rates across agents; about 40% of the shared tasks were borderline for only one agent).
- Efficiency: Codex flat (tool calls, output tokens and duration within about 3.8%). Claude: SELECTIVE used significantly fewer cache-creation tokens than NONE (p = 0.001, Holm 0.012), read by the author as a mechanical result of the delivery method.
- Test-running finding (exploratory, post hoc, not in the pre-registered efficiency family): on opshin, whose AGENTS.md warns that "the full test suite takes >20 minutes", Claude's wall-clock time was about 24% lower with context (NONE 2,689 s, ALWAYS ON 2,066 s, SELECTIVE 2,032 s; 4 of 5 tasks faster, sign-flip p = 0.125) and the number of full-suite pytest runs per cell fell NONE 3.67, ALWAYS ON 2.44, SELECTIVE 1.67 (4 tasks, p = 0.25). The paper calls this a process effect, not an outcome effect (correctness stayed null). It appears only for Claude and only on opshin (firebase went the opposite way, +82 s; Codex flat). For opshin the SELECTIVE and ALWAYS ON content is the same file, so this is the only measurement found here that compares always-loaded with on-demand delivery of the same test-running warning, but it is directional, underpowered, one repository, one agent, and the on-demand route is a wiki file, not a skill.
- Limits: 3 repositories, Python only, single author, injection channel differs between agents (system prompt versus user-prompt prepend), and Anthropic budget cap dropped two high-effort tasks from the Claude arm.
- Consistent in direction with [Gloaguen et al.](gloaguen-evaluating-agents-md.md) on correctness, with a wide bound.
