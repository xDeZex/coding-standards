# Matt Pocock, "Tactical vs Strategic Programming, and why I'm nervous for juniors" (X thread)

The X page itself returned HTTP 402. Content below comes from a search-engine snippet and summary of the thread, so wording is paraphrase except the quoted fragments.

- Opens: "Good programming involves a mix of tactical and strategic decision-making: Tactical: on the ground, short-term. The soldier doing the fighting. Strategic: high-view, long-term. The general planning the war."
- Tactician: writing good code, choosing syntax, file structure, how to test changes. Strategist: building code that lasts, designing architecture, automating away problems, thinking beyond today.
- Claims AI agents have eaten the tactical part, since tactical work can be bought below minimum wage; AI cannot code strategically; a developer's day is now "100% strategy".
- Worry for juniors: the traditional route was tactical tasks first, strategic experience accumulating slowly; he is nervous about pulling that bridge down.
- In the text seen, Ousterhout is not named. Thread wording ("soldier", "general", "war") is Pocock's own imagery, not Ousterhout's.
- Pocock's list puts "how to test changes" and "file structure" under tactical, which is a different cut from Ousterhout, for whom design of modules is strategic.
