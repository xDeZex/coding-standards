# Ousterhout, A Philosophy of Software Design, ch. 3 "Working Code Isn't Enough" (via reader notes)

Secondary: a reader's highlights of the book (2018, 2nd ed. 2021), not the book. Quotes are as the notes give them; the book itself was not read.

- Tactical: "In the tactical approach, your main focus is to get something working, such as a new feature or a bug fix."
- Strategic: "Your primary goal must be to produce a great design, which also happens to work."
- Tactical tornado: "Almost every software development organization has at least one developer who takes tactical programming to the extreme: a tactical tornado." A prolific coder, far faster than others, working in a totally tactical fashion, "rarely considered heroes by engineers who must work with their code in the future."
- Foundational point: "working code isn't enough."
- Search results also attribute to the chapter the investment idea (10-20% of time on design and refactoring), consistent with the lecture note. Not checked in the book text.
- Both are stances of a single programmer, applied to the code they write. Ousterhout does not map them to layers of a system.
