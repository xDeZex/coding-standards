# Genie Lessons: Nobody Wants Agents (Kent Beck)

How read this time: full post fetched with curl and converted to text (short post, read in full). All quotes were correct. Added context from the page: it is Genie Lesson #5 from a live session with Intent by Augment Code (a multi-agent tool with coordinator, implementer and verifier), on an adaptive radix tree in Go, and the post is marked as sponsored by Augment Code.

- "Nobody wants agents. Nobody wants agent swarms. I have a system and I want it to change. That's the whole thing."
- "I was managing it. Watching which agent was doing what. Wondering when to interrupt. Holding state in my head that the system should have been holding for me. I'd said I wanted readable code and instead I had a coordination problem."
- He wants to describe outcomes and "have the genie tell me if it's achievable and what it would take"; he says he has never managed two agents on one codebase at once "without my head exploding".
- "Multi-agent is a feature. Outcome-orientation is the thing the feature is supposed to deliver."
- "Right now, five agents can work on this codebase simultaneously. Five people can't. That's backwards." He says real-time collaborative augmented development, "where multiple humans actually steer together", is the real problem and "Nobody knows what that looks like."
- Bearing on the split: the human role in this post is coordination and outcome-setting, but Beck presents it as a burden and an unsolved problem rather than a settled division of labour. The post says nothing about tactical or strategic.
