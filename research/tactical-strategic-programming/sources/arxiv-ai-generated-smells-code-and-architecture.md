# AI-Generated Smells: An Analysis of Code and Architecture in LLM- and Agent-Driven Development

How read this time: PDF fetched from arxiv.org/pdf/2605.02741 and converted with pdftotext; read the abstract, introduction, setup for both experiments, results, statistical analysis, threats to validity and conclusion. Earlier note was based on the abstract only, and its "sample and models not recorded" gap is now filled.

Preprint (v1, 4 May 2026) by Yue Cai Zhu, Nikolaos Tsantalis and Peter C. Rigby (Concordia University). Not peer-reviewed as far as the PDF shows. Python only; smells detected with the static-analysis tool PyExamine.

- Experiment I: 90 problems sampled from the CodeContest dataset (the paper's threats section calls it a stratified sample); solutions from five LLMs (Gemini 2.5 Pro, Llama 3.3 70b, deepseek-coder-v2 16b, qwen3-coder 30b and 480b), under zero-shot and few-shot prompts, plus one randomly chosen human submission per problem as baseline. First-pass output only, with no debug-and-correct loop. Smell counts are small (for example Long Method: 11 for Qwen-480b zero-shot, 13 few-shot).
- Experiment II: five application scenarios, each with four prompts of increasing requirement detail, so about 20 repositories, all generated by one framework (MetaGPT) with one model (Qwen-Coder 480B). The paper acknowledges results may be specific to MetaGPT. Smell analysis in this experiment uses non-parametric statistics because of the small sample.
- Claims and their basis: "Volume-Quality Inverse Law" rests on Spearman correlations in Experiment II: total lines of code versus architectural smells rho = 0.94 (p < 0.001), versus structural smells 0.59, versus code-level smells 0.53; number of files versus architectural smells 0.72. Requirement specificity (stage) had no statistically significant effect on any smell category (p > 0.8). The paper reads this as prompt detail not preventing decay.
- "Reasoning-Complexity Trade-off" rests on Experiment I, where the larger or more capable models (Qwen-480b, Gemini 2.5 Pro) showed more Long Method smells. This is a comparison of a few models on small counts, so "decay grows with model capability" is a thin basis.
- "Functional correctness does not mitigate decay": the paper states running code was as likely to be structurally flawed as failed code.
- Conclusion quote: "future progress depends on equipping agents with explicit architectural foresight to ensure the software they build is not just functional, but also maintainable." The authors also conclude current agents behave like proficient "junior developers" lacking "senior architect" foresight; this is their interpretation.
- Bearing on the split: evidence that agent output can pass functional checks while showing structural smells, so it is relevant to whether code-level output is reliably good. Limits: Python, one multi-agent framework and one model for the architectural part, about 20 repositories, static-analysis smells as the quality proxy, no human baseline in Experiment II.
